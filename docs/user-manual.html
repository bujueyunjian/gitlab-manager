01 从首页选择任务

打开首页，在配置 Webhook与查询成员权限中选择本次任务。

两项任务都按仓库范围 → 检查与选择 → 配置 → 预览 → 结果推进。先核对目标，再确认具体变更。

检查并配置 Webhook →查询并设置成员权限 →

左侧可返回各自任务或查看任务记录。同一连接下，两项任务分别保留仓库范围；切换实例会清空连接相关的范围与表单。离开配置任务后，再次执行前需重新预览。

02 连接与仓库范围

首次连接

尚无连接时，选择任务后填写连接表单；成功后继续刚才选择的任务。

字段 填写方式
连接名称 便于区分实例的名称，例如“示例 GitLab”。
GitLab 实例地址 网页首页地址，例如 https://gitlab.example.com。支持端口和路径前缀，不添加 /api/v4。
个人访问令牌（PAT） 批量修改需要 api 范围，只查看可使用 read_api。权限仍由 GitLab 校验。

点击验证并保存连接。版本由应用自动识别；GitLab 13.10.5 无法报告令牌范围，显示“范围未知”时，连接成功也不代表具有写权限。

确定本次仓库范围

  1. 在选择仓库范围输入名称、namespace/project 或完整 Git URL，点击搜索。完整地址须属于当前实例；定位失败不会改做名称搜索。
  2. 结合归档状态与我的全部角色筛选。角色按当前账号的可见最高角色精确匹配，Developer 不包含 Maintainer 或 Owner。
  3. 勾选仓库。表头选择当前页；选择全部 N 个筛选结果加入整个筛选范围。展开本次范围 N 个仓库核对全部已选项目，必要时逐项移除。
  4. 核对本次范围后点击下一步：检查范围。翻页或搜索保留已选范围，隐藏项目仍可在“本次范围”中核对。

默认列出当前账号已加入的仓库；完整地址可补查其他有权访问的项目，列表不代表实例内全部仓库。

已有清单可点击批量粘贴，每行填写仓库 URL、demo/service-1 或应用名。点击查找仓库；同名结果须明确选择，再点击选择这些仓库加入本任务范围。完成数、失败数与耗时按实际响应推进；等待超过 10 秒时显示慢响应提示。

点击仓库名称或详情查看地址、角色与归档状态；在 GitLab 查看打开对应项目。

03 检查 Webhook 与选择目标

  1. 在 Webhook 任务完成仓库范围选择后，选择完整地址或名称（GitLab 17.1+），填写完整查询值并点击检查范围。
  2. 在未配置、已有配置、需处理之间查看结果。勾选本次要处理的仓库；表头只选择本组可处理项。
  3. 需要同时补齐与更新时，在“未配置”组勾选同时更新已有配置，再明确选择新增与更新的仓库。
  4. 核对本次选中数量，点击下一步：配置 Webhook。
分组 / 状态 处理方式
未配置 成功读取全部配置后未命中查询值，可选择新增；预览时仍会检查同址或同名配置。
已有配置 唯一匹配的配置可按具体 Hook ID 更新。匹配不代表事件、密钥或实际投递正确。
需处理 · 多条匹配 核对名称、地址与 ID，在该行明确选择具体 Hook。相同名称或地址不能作为自动改选依据。
需处理 · 读取失败 / 未检查 保留失败原因或未完成状态，不能据此判断缺失，也不会作为新增目标。

查询按完整文本精确匹配，地址末尾斜杠、协议或查询参数不同会视为不同地址。修改查询或仓库范围后需重新检查；停止检查等待当前请求结束后停止后续检查。旧版 GitLab 按地址管理，名称查询不可用。

需要查看其他现有配置时，点击查看范围内全部现有配置。可按仓库、名称和地址筛选；修改或删除只包含当前筛选中明确勾选的 Hook。读取失败项单独显示。

04 配置、预览与执行 Webhook

配置页带入刚才选择的仓库与具体 Hook。只选未配置项时新增；只选已有项时更新；混合选择会在同一次预览中分别列出新增与更新。

配置内容 规则
新增配置使用的 Webhook 地址 按名称检查后需补充接收地址。已有 Hook 仍按明确 ID 更新；要更换已有地址时单独勾选对应字段。
名称 GitLab 17.1 及以上可用。新配置需填写名称；已有项只在勾选“名称”时改名。
触发事件 支持 Push、合并请求、流水线、议题和标签。更新该字段时，勾选的开启、未勾选的关闭；未勾选整个字段时保持原配置，其他事件字段不在修改范围内。
设置新密钥 勾选后填写接收端约定的 Secret Token。已有密钥不回显；未选中时保持不变，空白不能清空已有密钥。
地址与 TLS 已有项可勾选后更换地址。“验证接收端证书”默认开启，由 GitLab 验证接收端证书。
  1. 点击扫描并预览，核对每个仓库的操作、具体变更、跳过和无法执行原因。所选字段一致时会跳过。
  2. 需要调整时点击返回修改；确认无误后点击确认执行。删除还需勾选额外确认。
  3. 进入当前任务的逐项结果。执行前会重新读取状态；配置已变化时，相关项可能被阻止，需要重新预览。

“仅新增”遇到同地址时跳过；存在同名异址配置时阻止新增。改名不能占用其他 Hook 的名称。重复选择失效后必须重新选择或重新查询，不会自动改选其他 Hook 或转为新增。

配置成功表示 GitLab 接受了设置。实际触发和投递需在 GitLab 的 Webhook 测试或接收端核实；跨仓库操作没有整体回滚。

05 查询与设置成员权限

  1. 从首页选择查询成员权限，确定本任务仓库范围并进入成员权限。
  2. 输入用户名或姓名，点击查找用户并明确选择账号。同名用户通过 @用户名 区分，不会自动选择第一项。
  3. 按用户全部角色或某个精确角色筛选，并结合全部授权状态查看结果。Developer 只包含可见最高角色为 Developer 的仓库。
  4. 勾选本次目标，核对“本次选中”，点击设置所选用户的直接权限。
授权状态 含义
有成员授权 在可见的直接或继承成员记录中找到此用户，显示较高角色与来源。
未查到成员授权 成员读取成功，未找到该用户，也未发现需单独核实的可见性、管理员或群组共享情形。
访问途径待核实 未找到成员记录，但管理员身份、公开或内部可见性、群组共享可能提供其他访问途径。
读取失败 / 未取得结果 缺少有效完整数据，不能判断缺少授权；失败原因独立保留。

仅成功读取且结论明确的已授权或缺失项可进入该用户的批量设置。刷新、切换用户、角色或筛选后重新核对选择；读取失败和待核实项不会自动加入。“未查到成员授权”不等于绝对无法访问，旧版共享成员或当前账号不可见的授权需在 GitLab 核实。

查看成员与共享群组

点击仓库名称或查看成员，在直接成员、继承或共享成员和共享群组之间查看角色、期限与来源。勾选直接成员后可修改授权或撤销授权，操作只包含当前仓库明确选择的直接成员。

同一用户可能同时具有直接和更高的继承权限，来源数量不相加。撤销直接成员不会移除其他来源的权限；继承或共享由来源群组管理。

配置并预览授权

核对已带入的用户与仓库，再设置 Guest、Reporter、Developer 或 Maintainer；不提供 Owner 授权。勾选设置到期时间后填写日期，留空表示长期有效；未勾选时保持原期限。已有直接成员可只修改角色或期限。

点击扫描并预览，核对新增、修改、跳过及受阻项；需要调整时返回修改，确认后点击确认执行。结果进入本任务的逐项记录。

其他授权 / 群组共享用于在当前选中的可用仓库范围内，搜索用户成员或已有群组共享。核对群组完整路径、角色和期限后预览；已有群组共享的角色调整需明确撤销再重新授权，应用不会隐式删除后重建。

06 查看与恢复任务

确认执行后，结果在当前任务的结果步骤显示。也可在左侧任务记录搜索操作、实例或仓库，点击查看结果；详情支持按状态筛选和搜索仓库、对象或原因。

状态 / 操作 处理方式
成功 / 跳过 成功表示本次请求完成；跳过原因见该项说明。
停止 / 继续未执行项 停止后不再派发新请求，已发出的请求继续完成。继续只处理未发送项。
失败 / 无法执行 先解决原因。“重试所选失败项”只重发勾选的失败项，不夹带其他未执行项；权限或状态冲突可能需要重新预览。
结果未知 请求可能已写入，先查询核实未知项，不要直接重发。密钥无法通过读取接口验证，需在接收端核实并按界面填写人工确认。
导出结果 选择保存位置并导出 JSON，包含仓库、对象、操作、最新状态、说明和尝试次数；分享前检查业务信息。

任务在本地 SQLite 保存每项最新状态、说明及累计尝试次数，可重启查看和导出；重试或核实会更新该项，不追加每次尝试的历史。查询与预览失败只在当前界面显示，不单独生成持久任务。

继续或重试要求重新输入密钥时，请再次填写；任务记录不会恢复密钥。任务执行期间关闭窗口会被阻止，应先停止并等待当前请求完成。

07 管理连接

在左下角连接中添加、编辑或检查实例。多连接时，右上角实例菜单和连接卡片的切换用于更换工作范围。

  • 检查连接：重新验证身份与连接状态，失败时根据提示检查令牌、范围和地址。
  • 编辑：调整名称、地址或替换 PAT；需重新输入令牌验证，更换地址时使用对应实例的令牌。
  • 移除连接：移除本地连接及系统凭据，不删除远端仓库或 Webhook。
  • 使用手册：用系统浏览器打开随安装包提供的本文件，可离线搜索、放大截图和打印。

从首页选任务后添加连接，会继续该任务；在连接页维护实例后，可返回首页开始操作。切换实例会清空两项任务的仓库范围与连接相关表单。

08 常见问题与数据保护

现象 先检查
HTTP 401 / 403 令牌有效性、所需范围及目标仓库管理权限。连接验证成功不代表有全部仓库的写权限。
HTTP 404 实例地址、路径前缀、资源是否存在及当前账号能否查看。实例地址不添加 API 路径。
无法进入下一步 核对仓库范围、检查结果和明确选中的目标；只读令牌、未处理冲突或正在扫描/提交时，相关入口不可用。
证书失败 应用到 GitLab 的 HTTPS 证书校验始终开启。Webhook 接收端证书由 GitLab 验证，应让 GitLab 信任正确 CA；关闭接收端校验会失去该连接的证书验证。
读取慢或有单项失败 查看完成数、失败原因与耗时。批量定位和资源读取最多四路并发；Webhook 检查可停止。预览较慢时先缩小范围，失败不会视为配置缺失。
无法保存令牌 检查 Windows 凭据管理器、macOS 钥匙串或 Linux Secret Service；系统请求授权时在系统窗口处理。

凭据与任务数据

  • PAT 保存在操作系统凭据存储中。Webhook 专用密钥只用于本次内存请求，不写入任务数据库或导出 JSON。
  • HTTP 错误只显示状态码、请求方法和固定提示，不保存失败响应正文。
  • 仓库路径、成员名称、URL 和备注属于业务数据，会出现在界面与任务中。不要把密钥放入 URL、名称或备注，公开截图或导出前检查内容。
  • 应用不收集遥测。本手册不发起网络请求，不读取应用连接、令牌或任务数据。

这是独立的开源客户端，与 GitLab 官方没有隶属关系。各系统安装和真实环境验收范围以项目 README 为准。

没有匹配的章节。试试“Webhook”“密钥”或“授权”，也可以清空搜索查看全部内容。
